# Shared Datasets

Courses in this track deliberately reuse the same data. Seeing the **same rows**
treated as an engineering problem, then an analysis problem, then a modelling
problem, then a security problem is most of what makes the connections between
courses visible.

Every dataset is **generated by code inside a lesson** — nothing is downloaded,
nothing is committed, and every one is reproducible from a seed.

---

## The two main datasets

### `orders` — a Cairo coffee chain

5,040 rows: branch, product, quantity, unit price, timestamp, customer id.
Carries deliberate defects — 120 nulls, 15 outliers of 50,000 EGP, and 40
duplicate rows.

| Course | Uses it for | Written by |
|---|---|---|
| [Data-Analysis Basic](Data-Analysis/Basic) | Exploring, cleaning, aggregation, trends, reporting | [lesson 02](Data-Analysis/Basic/lessons/02-exploring.md) |
| [Data-Analysis Advanced](Data-Analysis/Advanced) | Sampling, hypothesis tests, cohorts, segmentation | the cleaned version |
| [Data-Engineering](Data-Engineering) | Storage formats, incremental loading, quality checks | the same generator |

**The thread:** Data-Analysis lesson 03 finds that **1.1% of rows carry 58% of
reported revenue**. Data-Engineering asks how a pipeline would have caught those
rows before they reached anybody.

### `subscribers` — 12,000 SaaS customers

Plan, tenure, logins, support tickets, payment failures, country, age band, and
whether each cancelled within 30 days. Base rate 16.08%. Carries **two columns
recorded after the outcome**.

| Course | Uses it for | Entry point |
|---|---|---|
| [Data-Science](Data-Science) | The whole course: framing, leakage, thresholds, shipping, drift, fairness | [lesson 01](Data-Science/lessons/01-what-data-science-is.md) |
| [Data-Science 11-12](Data-Science/lessons/11-experiment-tracking.md) | Experiment tracking, prototypes | same file |
| [Data-Security-for-AI](Data-Security-for-AI) | Membership inference, extraction, poisoning — on a model you already understand | lessons 03-05 |
| [AI-Agents](AI-Agents) | The refund tools operate on the same customer world | [lesson 02](AI-Agents/lessons/02-tools.md) |
| [LLM-and-GenAI](LLM-and-GenAI) | The coffee-shop knowledge base for RAG shares the domain | [lesson 05](LLM-and-GenAI/lessons/05-embeddings-and-search.md) |

**The thread, and it is the most useful one in the track:**

```text
Data-Science 03    days_to_renewal leaks; AUC jumps 0.667 -> 0.946
Data-Science 06    the 0.5 threshold earns 1,083 EGP; 0.15 earns 47,313
Data-Science 10    a 10% holdout stays at 18.29% while the measured rate falls to 9.1%
Data-Security 03   the SAME model leaks membership at 0.805 AUC when overfitted
Data-Security 05   10,000 random queries clone it to 91.3% agreement
AI-Agents 05       an injected note refunds four of its customers for 1,610 EGP
```

Six courses, one population of customers, six different ways it can go wrong.

### `orders` / `customers` in SQL — the same shape, in a database

| Course | Uses it for | Entry point |

## Why generated rather than real

| | Generated | A real public dataset |
|---|---|---|
| Reproducible from a seed | **yes** | version drift |
| The ground truth is known | **yes** — we can show a method is wrong | never |
| Defects placed deliberately | **yes** — leakage, outliers, backdoors | accidental |
| No licence or privacy question | **yes** | often complicated |
| Realistic messiness | approximated | **yes** |
| Surprises the author did not plan | **no** | **yes** |

The last row is the real cost, and it is why **every project in this track
requires your own data.** The lessons use generated data so that a claim can be
checked against a known truth; the projects use real data so that you meet the
surprises.

## Using these across courses

Three exercises that connect courses, using data you already have:

1. **Run Data-Security lesson 03's membership-inference attack against the
   Data-Science lesson 05 model ladder.** Which of the four models leaks most,
   and does it match their train/test gaps?

2. **Take the Data-Analysis `orders` cleaning log into Data-Engineering lesson
   07.** Write the quality checks that would have rejected the 15 outlier rows
   at ingestion, and measure what the headline revenue number becomes.

3. **Point AI-Agents lesson 02's `refund_order` tool at the `subscribers`
   population**, apply Data-Science lesson 06's threshold as the eligibility
   rule, and measure the harm rate when an injected note tries to refund
   everyone.

4. **Build the `orders` schema from
   [Databases-and-SQL lesson 02](Databases-and-SQL/lessons/02-schema-design.md)
   and load the Data-Analysis `orders` fixture into it.** How many of the 175
   defective rows do the constraints reject? That number is the difference
   between cleaning data and preventing it.

5. **Compute the effective rank
   ([Foundations lesson 03](Foundations/lessons/03-decomposition.md)) of the
   `subscribers` feature matrix.** Eight columns — how many independent
   directions? Then check whether dropping to that many components changes
   [Data-Science lesson 05](Data-Science/lessons/05-baselines-and-selection.md)'s
   model ranking.

Each takes an afternoon and teaches more about how the courses fit together
than any amount of reading the READMEs.
